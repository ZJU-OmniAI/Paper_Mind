# Paper_Mind 功能说明

这是完整的功能文档。安装步骤见 [快速开始](../README_zh.md#快速开始)，首次使用可跟随 [收藏到找回的图文教程](walkthrough.zh-CN.md)：打开 `chrome://extensions` → 开发者模式 → 加载已解压的扩展程序 → 选择仓库里的 `extension/` 目录。

基础收藏、管理与本地检索不需要启动服务。只有选择本机 Claude Code / Codex 时，需要运行可选的 `npm run bridge`；直接使用模型 API 不需要桥接。

## 标签内专题分析

专题分析的定位是**比较同一标签下各篇论文的设计理念**：哪里相同、哪里不同、为什么。在 **标签库 → 某个标签 → 专题分析**点击**生成专题分析**，开始理解这一组论文。至少两篇论文有已保存材料后才开始；缺少材料的论文保留提示，不计入可分析进度总数。后台先逐篇提取方法画像，再综合全部画像，组织为五个视角：

- **全景**：核心结论；**设计空间图**把每篇论文放到两条宏观设计轴上（可切换横轴、纵轴），离得越近设计理念越接近；**理念光谱**逐条轴显示每篇论文偏向哪一端；**共同基础**矩阵用 ● 标出每条共同点由哪些论文具备；以及建议阅读顺序。
- **对照表**：每行一篇论文、每列一个设计问题，格子里是这篇论文的选择，同一列颜色相同表示做了同一种选择，没有比较的格子显示“·”。行按设计相似度排列（本地计算：同组选择的次数与共同基础），下方是**设计相似度热力图**和“最相近 / 分歧最大”的论文组合；点列名可查看该维度的**方法分支**（各组的方法、取舍与依据）。
- **选篇对比**：勾选本标签下 2–8 篇论文直接比较，见下节。
- **方法图**：逐篇用框图展示主要模块，以及材料支持的输入、步骤、分支和输出；资料未说明先后关系时展示结构分解，不强行串成流程。完整方法论述、取舍及个人笔记视角可展开阅读。
- **研究启发**：按“假设 → 对照 → 观察”查看研究方向与验证步骤，再展开材料依据、局限与开放问题。启发尚待验证，不表示已经完成查新或实验。想要更多灵感，可以从这里进入深度探索，把这个标签和其他标签的设计理念融合。

设计轴是模型从材料中归纳出的、论文之间真正拉开差距的宏观设计问题（例如“知识放在哪里”“何时核验”“训练还是免训练”）。每篇论文在轴上的位置（−2 到 +2）是依据已保存材料作出的**相对判断**，必须有这篇论文的依据，不是评分、实验结果或优劣排序；没有依据的论文不定位。图上点击圆点即可勾选论文，用于选篇对比。

方法路线按选定的设计维度分组，不表示年代、因果或优劣，也不枚举论文之间的两两连线。未归入当前维度分组的论文仍保留入口；材料不足时不强行归类。方法图区分流程与结构，只有保存证据支持的数据或控制顺序才显示流程箭头；结构从属和关联不画成时间顺序。共性、方法图与分组论述均可展开核对来源证据。建议阅读顺序表示学习路径，不是研究演进顺序。

界面优先展示少量短文字，完整报告和引用默认折叠，已有报告也能直接使用新布局。点击**展开看板**可使用更宽的阅读空间，按 Escape 收起。短预览只改变呈现方式，不裁剪已保存的报告或发送给模型的来源材料；打开视图、切换维度和展开内容都不会触发新的模型请求。

旧报告缺少设计空间图、理念光谱或方法图时，先用已有内容显示对照表、相似度热力图和结构块；点击**生成设计图表**可复用已保存画像，只重新综合补图。材料版本未变化的图会继续复用。设计轴、立场、图和短展示字段都是可选内容，格式不可用或缺少依据时只丢弃那一项，核心论述与引用校验仍严格；不会为凑图而编造步骤或位置。

每篇画像依据完整保存的摘要、个人笔记、记忆句和全部剪藏 Markdown；原摘要优先，缺少时才使用已保存译文。个人笔记是重点材料，但其中的理解、质疑与假设会与论文原文结论区分。来源摘录可用于核对，材料未提供的细节应标记为未知。输入不按字符数截取，不自动打开来源链接、补抓全文或执行笔记里的指令。

新增论文、修改摘要、个人笔记、记忆句或剪藏，或将论文移出标签，只会提示当前报告尚未覆盖这些变化，不自动调用模型。点击**更新分析**后，才补充新增论文画像、刷新变化的画像，并基于当前标签论文重新综合；其余画像复用。每篇已保存论文都会被纳入材料检查，不使用深度探索的 8 篇取样上限；材料不足会说明限制。

专题分析只由**生成专题分析 / 更新分析 / 重试**或明确的重新分析操作启动；打开标签、保存论文、启动浏览器不会发起新的分析。已经手动启动的任务会按点击时的当前资料在后台续跑，每步处理一小批画像或一次综合，显示**论文理解 N/M → 综合分析**进度并保存成功步骤。分析期间再修改资料，会提示再次点击更新后继续纳入变化。失败保留已完成画像及上一版分析，等待手动重试；专题分析没有自动触发开关。

默认沿用该标签上次成功使用的后端、模型和 effort；首次优先继承该标签原有的成功模型选择，没有时使用当前设置。该服务商的连接地址和凭据使用当前保存配置，模型不可用时明确报错，不静默换用其他服务商。展开**重新分析与模型**，可以**沿用模型重新分析**或**使用当前设置模型重新分析**；全量重做会刷新画像及综合结果，后续继续增量维护。

专题分析、来源摘录、缓存画像与进度保存在本机，并随 JSON 备份导出、导入。更新期间可能继续显示上次结果；删除或修改材料后，旧综合文字和摘录可能保留至成功更新，已导出的文件需单独管理。此功能分析库内材料，不联网查新或运行实验。

### 选篇对比

在**对照表**、设计空间图、理念光谱里点论文，或在**选篇对比**页勾选，选出同一标签下 2–8 篇有已保存材料的论文；可以填写想重点比较的问题，再点击**对比所选**。对比会完整读取所选论文已保存的文字（与专题分析的逐篇画像分开进行），结果包括：一句话核心结论、每篇的**设计立场**卡片、逐个设计问题的**对照表**（每格先给出简短的“选择”，相同选择同色显示，并标注“选择一致 / 各不相同”，再给出带原文摘录的说明）、**理念光谱**，以及共同点、关键差异和证据缺口。材料没有提供的格子标为未知，不填推测。

对比结果保存在这个标签下的对比记录里，可以继续追问（每次对比最多 20 次）、下载 Markdown，并随 JSON 备份导出、导入；所选论文必须都属于这个标签。打开对比页或切换记录不会调用模型。

## 深度探索：融合多个标签的设计理念

深度探索的定位是**融合多个标签的设计理念，获得更多灵感**。在管理页打开**深度探索**，使用模型设置里已配置的后端。左侧选择要融合的标签与已有会话，主体区域显示你的问题、智能体分析和后续问答。打开深度探索、切换标签或阅读历史报告不会触发模型请求；点击**开始融合**后才发送所选论文已保存的完整文字，包括摘要及译文、完整个人笔记和全部剪藏 Markdown，不按字符数截取，并附带已保存的论文信息、标签及链接预览。比较同一标签下的几篇论文，请使用该标签专题分析里的**选篇对比**。

### 选择标签与样本

选择 2–4 个不同标签（按点选顺序编号、配色），并可填写想要的灵感方向或约束。界面按标签轮流平衡取样最多 8 篇去重论文、优先较新的材料，运行前列出每个标签入选的论文，可以勾选调整，也可以恢复自动取样；每个标签至少要有一篇入选。这只是标签下论文的有限样本，不代表覆盖整个领域，也不构成新颖性证明。已做过专题分析的标签，会把那份分析的概要（结论、共同点、方法分组、设计轴）作为背景一起发送，帮助把握整个标签的设计思路；它只作参考，不当作证据。

### 融合报告

智能体先为每个标签提炼 2–3 条**设计理念**（例如“需要时才检索”“推理与行动交替”），每条都必须有该标签论文的原文摘录；再把不同标签的理念交叉组合成 2–4 个可检验的新想法，说明怎样组合、为什么可能带来新能力或化解矛盾，并给出最小实验方案、关键假设和风险。**融合图**左右（或左侧按标签分组）列出各标签的理念，中间是想法，连线表示“这个想法借用了这条理念”，悬停可高亮相关连线；每张想法卡片用“A 的理念 ＋ B 的理念 → 新想法”标明来源。每个想法的证据必须来自至少两个所选标签；缺少依据的理念会被去掉，不影响其余结果。

### 围绕报告继续对话

首次融合分析形成一份本地会话，可以在输入框继续追问，也可以使用智能体给出的建议问题。回答保留来源摘录；材料不足时，智能体说明缺失信息并建议下一步补充什么。每份报告最多保存 20 次追问；模型会参考来源快照、报告与自动研究概要，以及最近对话的压缩内容，并非逐字重读所有历史。失败或引用校验不通过时，不会保存半条问答，可以重试；已成功保存的问答保留。

### 自动研究 / AutoResearch

从生成的 idea 中选定一项，选择 1–3 轮自动研究。每轮根据来源材料及前序结果提出质疑、修订假设，并细化实验设计；可以据此梳理基线、消融、评价指标和失败条件。每份报告累计最多 3 轮，切换 idea 不会重置预算；这与 20 次对话追问的限额分别计算。轮数决定连续的模型调用次数，会使用所选后端的额度；可以请求本轮结束后停止，已完成的轮次保留。

第一版的 autoresearch 是**库内文字推演**：不联网检索新论文、不运行代码或实验，也不会证明假设成立。需要更完整的证据时，先将相关材料保存到库中，再发起新的分析。

### 研究报告与数据

- 每份报告本地保存对话历史、来源摘录和模型来源信息，可以再次打开、删除或下载 Markdown。以前在深度探索里做的论文对比：能归到某个标签的（所选论文都属于该标签）显示在那个标签的选篇对比记录里，其余在会话列表的“旧版论文对比”中继续可读。
- 报告随 JSON 导出、定时备份与导入一起保留；导入仍会替换当前库，先备份。
- 报告是生成时的快照。后来修改或删除原论文，不会同步更新已有报告中的来源材料或清除下载文件中的摘录。旧会话中曾截取的材料保持原样；更新资料后或要使用当前完整资料，请新建探索。
- 模型收到的内容包含选中论文的标题、来源链接、已保存的论文信息、标签详情、链接预览和完整保存的记忆句、摘要及译文、个人笔记、全部剪藏 Markdown（附各剪藏来源），以及研究问题；融合还包含所选标签已保存的专题分析概要；对话追问和自动研究还包含相关已有分析或对话上下文。不发送图片文件，也不自动打开来源链接。所选后端可能是远程服务，本机 CLI 也不等于离线推理。材料超出所选模型的上下文容量时，请求会明确失败，不会静默裁剪来源文字。

## 标签合并审核

在标签合并审核中生成整理建议，先查看候选标签的名称、说明和关联论文，再决定是否合并。模型提出的相似性或论文重叠是审核线索，不能代替语义判断：例如“检索增强生成”和“评估”可能共享论文，但仍应是不同标签。只有用户确认才执行合并；合并会迁移论文的标签关联和研究主题包的包含 / 排除条件。

审核卡显示每个标签的论文示例、合并后的去重论文数、共享论文数和受影响的主题包，并允许切换保留哪个标签。模型的把握程度是估计值，不代表可靠性保证。若确认前关联证据或主题包已变化，需要重新分析；分析失败不会将标签标记为已审核。

## 1.6.0：逐步找回论文

- **继续缩小范围**：选择标签后，论文列表上方展示当前结果中可继续细分的标签及加入后的准确篇数。计数同时考虑全文 / AI 搜索、阅读状态与评分；不推荐零结果或无法减少结果的标签。任一标签模式会提示先切换为包含全部。
- **看见当时的理解**：筛选和搜索结果突出显示完整记忆句，高亮文字命中，并标明来自标题、别名、笔记、摘要、剪藏正文或论文信息的依据。没有字面命中时不会编造摘录；AI 理由仍单独显示。
- **作者、年份和发表出处**：收藏时读取页面的学术引用元数据或 ScholarlyArticle JSON-LD；普通博客署名不会当作论文作者。作者用分号分隔，年份为四位数，会议 / 期刊可直接编辑。
- **补全已有记录**：详情 → 编辑 → 论文信息 → 补全空缺信息，查询 Semantic Scholar，必要时回退 Crossref。优先使用 arXiv / DOI；只有标题时要求规范化后完全一致且结果无歧义。查询可能受网络、收录范围和限流影响，缺失项可手动填写。
- 补查不覆盖已填内容或查询期间的编辑；核对后点击保存。作者、年份和发表出处支持搜索并随 JSON 备份保留。旧记录默认为空，不根据收藏时间猜发表年份，也不由 LLM 编造事实。

## 数据保存位置

- 论文、标签、摘要、记忆句、阅读状态、备注、专题分析和研究报告（含来源摘录）保存在插件的 IndexedDB 本地数据库中。
- 每日下午 4 点自动 JSON 备份会下载到 Chrome 默认下载目录；如果希望保存到桌面，可以把 Chrome 默认下载位置设为桌面。
- 模型设置和可选 API Key 保存在 `chrome.storage.local`。
- 不需要注册账号。
- 如果使用 LLM 功能，可在模型设置选择本机 Claude Code / Codex，或配置 Qwen、智谱、Kimi、DeepSeek、通用兼容 API。参见 [模型接入说明](local-models.md)。

## 导入 / 导出

在“管理”页面进入“模型设置”，底部有“数据导入 / 导出”：

- “本地 JSON 导入 Chrome”：可以选择旧本地服务的 `data/store.json`，也可以选择本插件之前导出的 JSON。
- “从 Chrome 导出本地 JSON”：会把当前 Chrome IndexedDB 里的论文、标签、专题分析和研究报告下载成本地 JSON 备份。
- 插件也会每日下午 4 点自动下载一份 JSON 备份到 Chrome 默认下载目录。
- API Key 不会随论文标签数据一起导出。

## 网页剪藏（v1.3）

不只是论文页——公众号文章、博客、知乎回答等任意网页，点插件图标即可整篇存成一条"论文"记录。

- 打开弹窗时自动抽取当前页正文，面板显示「已读到正文 N 字 · M 张图」，勾选框控制是否保存正文
- 正文转成 Markdown 保存，标题层级、列表、引用、代码块、表格、视频链接都会保留；开头一段自动填进「摘要」
- 详情页的「简介」区域直接渲染网页正文（含图片），超过一屏折叠，点正文或「展开全文」展开
- 编辑论文时多出「网页正文」输入框，可以直接改 Markdown；清空即删除剪藏
- 分享链接里的一次性参数（公众号 `chksm`/`scene`、小红书 `xsec_token` 等）会被忽略，同一篇文章换个分享链接再存也不会重复入库
- 正文内容参与论文库的本地搜索，记得文章里某句话就能搜到
- arXiv / alphaXiv 这类论文页默认不勾选剪藏（那里的摘要走官方 API 更干净），需要时手动勾上即可

### 图片存在哪

图片会下载成**磁盘上的真实文件**，不留在浏览器里：

```text
<Chrome 下载目录>/Paper_Mind剪藏/<日期>-<标题>-<论文ID后6位>/01-xxxx.jpg
```

- 序号就是图片在正文里的顺序，扩展名按实际图片格式定（公众号 URL 里的 `wx_fmt` 经常是错的）
- 下载在后台进行，保存后不用等；完成会弹提示。下载记录会自动从下载列表里抹掉（文件保留），免得一篇几十张图刷屏
- 为什么要下载而不是直接引用原图：公众号图床按 Referer 防盗链，直接引原地址只会拿到一张 2KB 的"未经允许不可引用"占位图；存到本地后，原文被删也还能看
- 想换位置：把 Chrome 的下载目录改掉，或给 `~/Downloads/Paper_Mind剪藏` 做个软链接指到别处
- **删除论文不会删磁盘上的图片**，那是你的存档，要清理请自己去文件夹里删

### 需要开一次的开关

Chrome 默认不允许扩展读本地文件，所以第一次用要去 `chrome://extensions` → Paper_Mind → 打开**「允许访问文件网址」**，管理页才能把磁盘上的图显示出来。

没开也不会白屏：图片会自动回落到网页原图，同时正文上方会显示一条提示告诉你去哪打开。

### 论文和它的解读文章归成一条（v1.3）

一篇论文往往还有公众号解读、知乎回答等多份材料，它们讲的是同一件事，没必要存成好几条。

- **自动配对，两个方向都认**：
  - 先有论文、后剪解读 → 解读正文里出现论文的 **arXiv 编号 / DOI / 标题** 时提示「这篇像是《XXX》的解读」
  - 先剪解读、后存论文 → 打开 arXiv 等论文页时，发现库里某条解读引用了同一个编号，提示「库里已经存过这篇论文的解读《XXX》」
  - 两种情况都是「并入这篇 / 单独保存」二选一，只认上面三种硬证据，认不出来就不打扰你
  - arXiv 编号支持 arxiv.org / alphaXiv / ar5iv / HuggingFace papers / `arXiv:xxxx.xxxxx` / DOI 形式，从哪个入口存论文都认得出
- **并入的效果**（按谁是"正主"决定）：
  - 并入的是解读 → 作为**一份材料**挂到论文下，论文的标题和摘要不动
  - 并入的是论文本身 → 记录的标题、摘要、来源换成论文的（解读的标题不该占着正主位置），已存的解读作为材料保留，摘要译文作废等后台重译
  - 两种情况标签都会合并过去
- **详情页分区展示**：「网页正文 · N 份材料」，每份有自己的标题、来源、字数和图片状态，可以单独展开、单独重下图片、单独删除
- **图片各自成文件夹**：`Paper_Mind剪藏/<日期>-<论文标题>-<id>/<序号>-<材料标题>/`
- **已经存成两条了怎么办**：打开其中一条 → 右上角「并入另一篇」→ 选目标论文。剪藏材料、外部链接、标签都会搬过去，原来那条消失
- 同一个来源再剪一次算更新（留正文更全的那版），不会重复堆材料

### 从 v1.1 升级

v1.1 把图片存在浏览器 IndexedDB 里。升级后打开旧剪藏，插件会自动把这些图搬到磁盘（直接用已有副本，不重新联网），搬完就把浏览器里的副本删掉。

v1.2 及更早每条记录只能挂一份剪藏（`clip` 字段），升级后会自动变成 `clips` 数组的第一份，不用手动处理。

每日 JSON 备份里只有正文和图片路径，没有图片二进制，所以备份不会被撑大。

## 功能

- 自动读取当前标签页标题（优先使用学术页面的 `citation_title`，arXiv 编号前缀会自动去掉）
- 尝试读取页面摘要（含 `citation_abstract`、arXiv abstract）、一级标题和选中文本
- 点击“粘贴剪贴板”时，才将剪贴板文本填入“备注 / 对话记录”；打开弹窗不会自动读取
- 可以手动填写标题、摘要、备注/对话记录
- 标签为芯片式输入：输入即搜索已有标签，回车添加，Backspace 删除最后一个；输入框下方提供常用标签一键添加
- 打开弹窗即自动检测当前页面是否已收藏过：已收藏会显示绿色横幅，保存按钮变为「合并更新已有论文」，不会产生重复条目
- 保存新论文时如果库里有标题高度相似的论文，会提示确认「仍然新建 / 取消」（不提供合并，避免误操作）
- ⌘+Enter（Windows 为 Ctrl+Enter）快捷保存
- 未选择标签保存时会自动进入“待归类”系统标签
- 研究主题包可以按多个包含/排除标签实时聚合论文
- 论文库和标签库支持本地快速检索，不需要调用 LLM
- 标签库支持本地冗余分析，找出论文集合完全一致的标签合并建议
- 管理页论文卡片整卡可点击进入详情，卡片上显示收藏日期与来源域名
- 弹窗和管理页均跟随系统自动切换浅色 / 深色模式
- 点击“管理”打开完整插件管理页
- 管理页支持论文库、标签库、智能检索、标签合并审核、相似论文推荐和模型测试


## 1.4：精简标签与论文发现

- 默认从论文库开始；搜索名称、别名、标签说明、摘要 / 译文、笔记、链接与完整剪藏正文。关键词以空格组合，短语可加引号。
- 标签交集 / 并集筛选、评分筛选、分页、清除条件和 `⌘ / Ctrl K` 快捷搜索。
- 每篇论文和整个论文库的标签数量都不设上限（1.5.1 起）；旧上限设置不再生效，名称复用与别名仍可避免重复。
- 每次最多显示 8 个相关标签候选，支持上下键与 Enter 选择。标签卡片显示说明，标签详情显示完整说明与生成来源。
- 模型根据人工标签与最多 6 篇关联论文的摘要、笔记和剪藏片段生成说明；后台分批、缓存、自动更新、失败保留旧内容并提供重试。
- 合并标签会迁移研究主题包的包含 / 排除条件。论文集合相同仅作为审核线索，不再表达为语义同义的确定证据。


## 1.5：从记忆中的概念找回论文

- 论文库顶部从概念出发，先给出已有标签的本地匹配；AI 可理解自然语言，最多返回 6 个已存在的标签和理由。选择标签后查看关联论文，不把原概念句当作全文筛选，不自动造标签。
- 收藏、手动添加和详情编辑均可填写 280 字以内的“一句话记住它”。论文卡片显示记忆句，全文检索及模型上下文会使用它。
- 阅读状态“未读 / 在读 / 已读 / 待重读”独立保存，支持详情快捷更新和论文库筛选，不占标签配额。
- 导入旧数据时保留所有原标签，缺少新字段的记录默认为未读、空记忆句；不猜测历史标签含义。合并论文保持目标阅读进度，不同记忆句保留到笔记。
- 可选本机桥接使用已登录 CLI；通用 API 支持 Chat Completions，参数不兼容时可关闭 JSON mode。账号凭据不从 CLI 复制到插件，插件连接码和 API Key 不进入备份。
- 详见 [本机模型与 API 配置](local-models.md)。

## 1.5.1 模型与 effort 选择

- Claude Code / Codex 分别保存模型和思考强度，可刷新本机模型目录，也可填写自定义 ID。目录提供能力信息时，effort 下拉框随模型联动；不支持的原档位在切换模型时恢复默认。
- 检测连接后自动读取目录，不发起模型生成；刷新失败保留当前选择。默认模型和默认 effort 均不向 CLI 强加对应参数。
