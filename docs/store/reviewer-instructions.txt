Paper_Mind 1.6.0 — reviewer test instructions

PURPOSE AND ACCESS
Paper_Mind is a local research-paper library organized by tags, concepts and personal memory sentences. Core features require no account, payment, API key or companion process. The extension ZIP is standalone. The optional bridge is NOT required to start reviewing.

START WITH A FRESH PROFILE
Use a new Chrome profile for the sample library. JSON import REPLACES the current library; it is not an append operation. Do not import this fixture into a personal library without exporting it first.

1. Install the submitted extension, pin its action and open it on a normal HTTPS page. chrome:// pages and the Chrome Web Store itself do not allow page extraction. Review the detected title and source URL, add two tags and a short memory sentence, choose a reading status, and save.
2. Open the library from the popup. The manager also opens through the extension's Options entry on chrome://extensions. Use the language selector to choose English or 简体中文. Confirm the saved record, its multiple tags, memory and reading status.

REPRODUCIBLE SAMPLE LIBRARY
Optional, synthetic fixture with nine papers, no account data or API keys:
English: https://raw.githubusercontent.com/ZJU-OmniAI/Paper_Mind/main/docs/store/reviewer-library-en.json
Chinese: https://raw.githubusercontent.com/ZJU-OmniAI/Paper_Mind/main/docs/store/reviewer-library-zh.json

Download the appropriate JSON. In the manager, open Model settings, scroll to Data import / export, choose the JSON import button and confirm replacing the fresh profile's library. Importing the file does not configure a model. The fixture's author names, venue and tag descriptions are illustrative; descriptions are prewritten examples, not evidence of a live model request.

LOCAL FLOW TO TEST
1. Open Library. The fixture has 9 papers. Enter “agent optimization” (English fixture) or “智能体优化” (Chinese fixture) in the concept field. Local name/alias/description matching shows the existing tag without calling AI.
2. Select Agent optimization / 智能体优化. The library now shows 3 papers.
3. In Narrow it down further / 还可以怎样缩小范围, select Evaluation / 评估与可靠性. The suggestion shows 2 left / 剩 2 篇, and the combined filter returns 2 papers.
4. Find “Reading Papers with Evidence-Aware Agents”. The result directly shows “Verify tool evidence before an agent answers questions about a paper.” / “先验证工具返回的证据，再让智能体回答论文问题。” It has BOTH selected concept tags, a separate Reading / 在读 state and demo authors/year/venue.
5. Open the paper, edit its memory or reading status, save and reopen it. Reading status does not create an extra concept tag.
6. Open Tags and select the agent tag. Inspect its description, aliases and linked papers. Search does not create tags. Generating a new description requires an optional model; the provided description is explicitly a demo.
7. Export the library from Settings. Inspect the JSON: records and image paths are included; API keys and bridge tokens are excluded.

OPTIONAL NETWORK FEATURES
On an actual scholarly page, inspect detected authors, year and venue. “Fill missing details” can query Semantic Scholar / Crossref using an identifier or title. It fills only blank fields for review; service rate limits or incomplete records may leave fields empty. Saved clips can download images into Chrome's downloads directory; enable “Allow access to file URLs” only if you want the extension to show those local files. Removing a record does not remove downloaded files from disk.

OPTIONAL AI — API ROUTE
In Model settings, choose Compatible API, set your service's Chat Completions base URL and model ID, and provide a key if required. Remote services require HTTPS. A local compatible service can use a supported localhost HTTP address. Leave JSON mode off unless supported by that service. Save, then use Test model. Try AI match existing tags or Regenerate description on a sample tag. Relevant text is sent to this chosen backend. Automatic tag descriptions are enabled by default and can be disabled; saving may also trigger abstract translation and library recommendations.

OPTIONAL AI — LOCAL CLI ROUTE
Install a recent Claude Code or Codex CLI and sign in with an authorized test account. Clone the public source repository, use Node.js 22+, and run “npm run bridge” in its root; no npm install is needed for this bridge. Paste the printed http://127.0.0.1:39321 address and private connection token into Model settings. Choose Claude Code or Codex, check the connection, choose a model and supported effort, save and test. Keep the bridge terminal running. The CLI may contact a remote model service; “local” describes the bridge connection, not offline inference.

No shared model credentials are included in this public repository. If independent AI access is required for review, the publisher should supply a limited test credential privately in the dashboard or respond to the reviewer; it must never be added to this file or the sample library. Model availability and costs depend on the configured service.

IMPLEMENTATION AND SUPPORT
All extension code is bundled in the ZIP. Metadata and model responses are data, not remotely hosted JavaScript. The separately installed bridge accepts fixed CLI operations and is optional.
