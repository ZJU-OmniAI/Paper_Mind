# Chrome 扩展安装说明

这个扩展是独立的本地优先Paper_Mind，不需要启动 `server.js`，也不需要本地 companion service。

## 安装扩展

1. 打开 Chrome，进入 `chrome://extensions`
2. 打开右上角的“开发者模式”
3. 点击“加载已解压的扩展程序”
4. 选择这个目录：

```text
/Users/mayanna/Desktop/Agent开发/Paper_Mind/extension
```

5. 建议把扩展固定到工具栏，之后点击图标即可快速添加论文。

## 数据保存位置

- 论文、标签、摘要和备注保存在插件的 IndexedDB 本地数据库中。
- 每日下午 4 点自动 JSON 备份会下载到 Chrome 默认下载目录；如果希望保存到桌面，可以把 Chrome 默认下载位置设为桌面。
- 模型设置和可选 API Key 保存在 `chrome.storage.local`。
- 不需要注册账号。
- 不需要启动 `127.0.0.1:5173`。
- 如果使用 LLM 功能，需要在“管理”里的模型设置页填写自己的 Qwen 或智谱 API Key。

## 导入 / 导出

在“管理”页面进入“模型设置”，底部有“数据导入 / 导出”：

- “本地 JSON 导入 Chrome”：可以选择旧本地服务的 `data/store.json`，也可以选择本插件之前导出的 JSON。
- “从 Chrome 导出本地 JSON”：会把当前 Chrome IndexedDB 里的论文和标签下载成本地 JSON 备份。
- 插件也会每日下午 4 点自动下载一份 JSON 备份到 Chrome 默认下载目录。
- API Key 不会随论文标签数据一起导出。

## 网页剪藏（v1.3）

不只是论文页——公众号文章、博客、知乎回答等任意网页，点插件图标即可整篇存成一条"论文"记录。

- 打开弹窗时自动抽取当前页正文，面板显示「已读到正文 N 字 · M 张图」，勾选框控制是否保存正文
- 正文转成 Markdown 保存，标题层级、列表、引用、代码块、表格、视频链接都会保留；开头一段自动填进「摘要」
- 详情页的「简介」区域直接渲染网页正文（含图片），超过一屏折叠，点正文或「展开全文」展开
- 编辑论文时多出「网页正文」输入框，可以直接改 Markdown；清空即删除剪藏
- 分享链接里的一次性参数（公众号 `chksm`/`scene`、小红书 `xsec_token` 等）会被忽略，同一篇文章换个分享链接再存也不会重复入库
- 正文内容参与论文库的本地搜索，记得文章里某句话就能搜到
- arXiv / alphaXiv 这类论文页默认不勾选剪藏（那里的摘要走官方 API 更干净），需要时手动勾上即可

### 图片存在哪

图片会下载成**磁盘上的真实文件**，不留在浏览器里：

```text
<Chrome 下载目录>/Paper_Mind剪藏/<日期>-<标题>-<论文ID后6位>/01-xxxx.jpg
```

- 序号就是图片在正文里的顺序，扩展名按实际图片格式定（公众号 URL 里的 `wx_fmt` 经常是错的）
- 下载在后台进行，保存后不用等；完成会弹提示。下载记录会自动从下载列表里抹掉（文件保留），免得一篇几十张图刷屏
- 为什么要下载而不是直接引用原图：公众号图床按 Referer 防盗链，直接引原地址只会拿到一张 2KB 的"未经允许不可引用"占位图；存到本地后，原文被删也还能看
- 想换位置：把 Chrome 的下载目录改掉，或给 `~/Downloads/Paper_Mind剪藏` 做个软链接指到别处
- **删除论文不会删磁盘上的图片**，那是你的存档，要清理请自己去文件夹里删

### 需要开一次的开关

Chrome 默认不允许扩展读本地文件，所以第一次用要去 `chrome://extensions` → Paper_Mind → 打开**「允许访问文件网址」**，管理页才能把磁盘上的图显示出来。

没开也不会白屏：图片会自动回落到网页原图，同时正文上方会显示一条提示告诉你去哪打开。

### 论文和它的解读文章归成一条（v1.3）

一篇论文往往还有公众号解读、知乎回答等多份材料，它们讲的是同一件事，没必要存成好几条。

- **自动配对，两个方向都认**：
  - 先有论文、后剪解读 → 解读正文里出现论文的 **arXiv 编号 / DOI / 标题** 时提示「这篇像是《XXX》的解读」
  - 先剪解读、后存论文 → 打开 arXiv 等论文页时，发现库里某条解读引用了同一个编号，提示「库里已经存过这篇论文的解读《XXX》」
  - 两种情况都是「并入这篇 / 单独保存」二选一，只认上面三种硬证据，认不出来就不打扰你
  - arXiv 编号支持 arxiv.org / alphaXiv / ar5iv / HuggingFace papers / `arXiv:xxxx.xxxxx` / DOI 形式，从哪个入口存论文都认得出
- **并入的效果**（按谁是"正主"决定）：
  - 并入的是解读 → 作为**一份材料**挂到论文下，论文的标题和摘要不动
  - 并入的是论文本身 → 记录的标题、摘要、来源换成论文的（解读的标题不该占着正主位置），已存的解读作为材料保留，摘要译文作废等后台重译
  - 两种情况标签都会合并过去
- **详情页分区展示**：「网页正文 · N 份材料」，每份有自己的标题、来源、字数和图片状态，可以单独展开、单独重下图片、单独删除
- **图片各自成文件夹**：`Paper_Mind剪藏/<日期>-<论文标题>-<id>/<序号>-<材料标题>/`
- **已经存成两条了怎么办**：打开其中一条 → 右上角「并入另一篇」→ 选目标论文。剪藏材料、外部链接、标签都会搬过去，原来那条消失
- 同一个来源再剪一次算更新（留正文更全的那版），不会重复堆材料

### 从 v1.1 升级

v1.1 把图片存在浏览器 IndexedDB 里。升级后打开旧剪藏，插件会自动把这些图搬到磁盘（直接用已有副本，不重新联网），搬完就把浏览器里的副本删掉。

v1.2 及更早每条记录只能挂一份剪藏（`clip` 字段），升级后会自动变成 `clips` 数组的第一份，不用手动处理。

每日 JSON 备份里只有正文和图片路径，没有图片二进制，所以备份不会被撑大。

## 功能

- 自动读取当前标签页标题（优先使用学术页面的 `citation_title`，arXiv 编号前缀会自动去掉）
- 尝试读取页面摘要（含 `citation_abstract`、arXiv abstract）、一级标题和选中文本
- 打开弹窗添加论文时，会尝试把剪贴板文本填入“备注 / 对话记录”
- 可以手动填写标题、摘要、备注/对话记录
- 标签为芯片式输入：输入即搜索已有标签，回车添加，Backspace 删除最后一个；输入框下方提供常用标签一键添加
- 打开弹窗即自动检测当前页面是否已收藏过：已收藏会显示绿色横幅，保存按钮变为「合并更新已有论文」，不会产生重复条目
- 保存新论文时如果库里有标题高度相似的论文，会提示确认「仍然新建 / 取消」（不提供合并，避免误操作）
- ⌘+Enter（Windows 为 Ctrl+Enter）快捷保存
- 未选择标签保存时会自动进入“待归类”系统标签
- 研究主题包可以按多个包含/排除标签实时聚合论文
- 论文库和标签库支持本地快速检索，不需要调用 LLM
- 标签库支持本地冗余分析，找出论文集合完全一致的标签合并建议
- 管理页论文卡片整卡可点击进入详情，卡片上显示收藏日期与来源域名
- 弹窗和管理页均跟随系统自动切换浅色 / 深色模式
- 点击“管理”打开完整插件管理页
- 管理页支持论文库、标签库、智能检索、标签合并审核、相似论文推荐和模型测试
