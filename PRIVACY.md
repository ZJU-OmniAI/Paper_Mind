# Privacy Policy

Last updated: 2026-10-10 · [简体中文](PRIVACY_zh.md)

Paper_Mind stores paper titles, authors, publication years, venues, abstracts, personal memory sentences, reading status, notes, clips, tags, topic packs, per-tag topic analyses (including paper profiles, source excerpts and saved progress) and research reports (including conversations and source excerpts) in the extension's local IndexedDB database. Model settings, optional API keys and the optional bridge connection token are stored in `chrome.storage.local`. The extension does not require a Paper_Mind account, operate a remote library service, collect analytics or sell data.

The extension may create a daily JSON backup at 4 PM local time through Chrome's downloads API. Backups include library records, reading progress, topic analyses and research reports with their source excerpts, but exclude model API keys and bridge tokens. They are saved to the user's configured Chrome downloads location.

Saved content may include names (such as paper authors), source-page URLs, personal notes and conversation excerpts that the user chooses to keep. Paper_Mind does not continuously record browsing history, monitor keystrokes or read other tabs in the background. Local storage is not a claim of application-level encryption; protect the Chrome profile, downloaded backups and computer as you would other personal files.

Clipboard text is read only when the user clicks “Paste clipboard”. Opening the popup does not read the clipboard. Pasted text is stored only if the paper is saved.

Web clipping reads the main content of the current page when the popup opens to offer it as a clip. Text is saved only when the user keeps “Save page content” enabled and saves the entry. Images referenced by saved clips may be downloaded without cookies, credentials or a referrer to a “Paper_Mind剪藏” folder in the Chrome downloads directory. Deleting an entry removes its image records from the extension but does not delete downloaded files from disk. Citation counts and link previews may query their respective metadata services or source websites.

## Publication details

The capture popup reads academic citation metadata, scholarly JSON-LD and a few well-known page layouts (IEEE Xplore, ScienceDirect, academic project pages) from the current page to suggest the title, authors, year, venue and abstract. These fields are editable and are stored locally only when saved.

When the page cannot be read (for example a PDF opened in another extension's reader) or its details are incomplete, the popup looks the paper up by an identifier in the page address: an arXiv ID (arXiv API, or the arXiv abstract page), an OpenReview ID (OpenReview API), a conference PDF's landing page, or a DOI (Semantic Scholar, then Crossref). On code repositories and project pages, an arXiv paper linked from the page is used only if its title matches the page. Only PDFs, reader pages and paper sites without an identifier are looked up by exact title on arXiv, Semantic Scholar or Crossref; commentary pages such as WeChat articles are not. Requests to OpenReview and to landing pages carry the browser's own cookies for those sites, as visiting them would; the other services receive no cookies. Notes, selected text and clipped content are not sent. If a paper is saved before the lookup finishes, the same lookup runs once in the background for fields that are still empty. **Fill paper details** in the library and **Fill missing details** in a paper's editor run these lookups on demand. Results only fill blank fields (or replace an abstract that is a truncated preview) and never overwrite edits. Publication facts are not generated by a model. Citation-count lookups remain available.

## Optional model processing

Connecting a model enables requests to the user's selected backend: Qwen / DashScope, Zhipu GLM, Kimi Code, DeepSeek, a configured Chat Completions-compatible API, or a signed-in local Claude Code / Codex CLI. These model services process text under their own policies. A local CLI is a local connection method, **not a guarantee of offline inference**. A locally hosted compatible model can be used through the API settings.

Manual model operations include concept-to-tag matching, semantic paper search, similar-paper recommendations, translation, model tests and tag-merge suggestions. Concept matching may send the query and the existing tag catalog, including names, aliases, descriptions, and up to eight linked paper titles and memory sentences per tag. Other operations send the paper text needed for their respective tasks.

Paper comparisons inside a tag’s topic analysis, and cross-tag fusion, follow-up conversations and automatic idea research in Deep exploration, are user-triggered. Before starting, the interface displays the source-paper selection and explains the text that will be sent. A run sends at most eight saved papers (all from that tag for a comparison), including identifiers, titles, source URLs, saved paper information and tag details, the complete saved memory sentences, abstracts and translations, personal notes and Markdown from every clip, plus each clip’s saved provenance and saved link previews, together with the user's research question. Cross-tag fusion also sends the saved topic-analysis summaries of the 2–4 chosen tags (takeaway, shared foundations, method groups and design axes) as background, not evidence. A reply that fails format or quote validation is sent back once with the same inputs for correction. New explorations do not truncate these source texts by character count. Follow-up requests reuse the saved source snapshot and also send relevant earlier analysis and conversation context. The chosen backend may reject material that exceeds its context capacity; source text is not silently shortened. Each report supports up to 20 saved follow-up exchanges. Automatic research sends the selected idea and relevant earlier analysis, with a separate budget of 1–3 sequential model rounds chosen by the user. Image files and model credentials are not included in the research source material. Opening the chat or a saved report does not trigger these operations. The chat does not open source links automatically, search external literature or execute experiments.

Research reports, their follow-up questions and answers, source snapshots, quoted excerpts and model provenance are retained locally and included in JSON backups. Model requests use condensed analysis and recent conversation excerpts rather than the full saved conversation verbatim. Users can delete reports with their conversation history or download them as Markdown. Reports are snapshots: deleting or editing a source paper does not erase text already saved in a report, conversation or exported file. Older reports with excerpted source snapshots remain excerpted; start a new exploration to use the complete current material. Manage those reports and files separately when removing sensitive content.

After a model is configured, saving a paper may also trigger background abstract translation and similar-paper recommendations. With automatic tag descriptions enabled (the default), saving papers or updating tags may send each tag's name, aliases and excerpts from up to six linked papers. Each paper contributes at most 280 characters of memory, 2,400 of abstract, 1,200 of notes and 3,600 of clip text. Image files are not sent for tag descriptions. Generated descriptions, provenance and failure state are stored locally. Automatic descriptions can be disabled in Settings; manual generation remains available.

Topic analysis starts only when the user clicks to generate, update, retry or fully reanalyze a tag. Adding or editing papers, deleting papers or changing tag membership only marks the report as not covering the changed material; these actions do not start topic-analysis model calls. A requested update processes current material, refreshing new or changed paper profiles and synthesizing the current paper set into an overview, commonalities, differences and tradeoffs, research inspirations, reading suggestions and open questions. Started tasks can continue in the background and save progress. Later source changes require another click to include them. Opening a tag or starting the browser does not initiate a new analysis.

Profile requests send the selected tag’s relevant paper IDs and titles, complete saved abstracts, personal notes, memory sentences and all clip Markdown. The original abstract is preferred, with the saved abstract translation used only when it is empty. The synthesis uses the tag’s completed paper profiles and their retained evidence, which can contain excerpts from personal notes and memories. Unrelated papers, image files and model credentials are not included as source material. The feature does not open links, search the web or run experiments. Source text is not truncated by character count; the backend can reject material that exceeds its capacity. Personal notes are treated as the user’s understanding or hypotheses, and generated inspirations require validation.

Each background step saves a small batch of completed profiles or a synthesis result. Cached profiles, source versions, excerpts, model provenance, generation/failure state and progress remain local and are included in JSON backups. Failed calls retain completed work and the prior analysis; retries can reuse that progress. Failed tasks wait for a manual retry. Source changes mark the analysis for updating, and earlier synthesized text or excerpts can remain until a successful refresh. Removing papers or tag membership removes their profiles; removing a tag removes its analysis. Exported files require separate management when removing sensitive text. Existing graph records from earlier versions can remain in local library data and backups for compatibility.

Analysis retains each tag’s last successful provider, model and effort. First use inherits an existing successful model choice for that tag, or current settings. Connection settings and credentials use that provider’s current saved configuration. An unavailable model produces an error rather than silently switching to another provider; users can explicitly adopt current settings for full reanalysis. Model provenance can include the endpoint used, but not the provider’s credentials. There is no automatic topic-analysis setting; each new analysis or update requires an explicit action. Deep exploration remains the separate user-triggered workflow described above.

## Optional local bridge

The optional bridge runs when the user starts `npm run bridge` or installs its macOS background service with `npm run bridge:install`. It listens on `127.0.0.1`, requires a random connection token, checks Host and Origin, and accepts only the supported fixed CLI operations. The default token file is `~/.paper-mind/bridge-token`, restricted to the current user. Neither the bridge nor the extension copies CLI login credentials into the library.

Prompts are sent to child processes over stdin. Requests run in temporary directories and their temporary answer files are removed on completion or failure. Claude uses no-session-persistence with tools, MCP and hooks disabled. Codex uses ephemeral execution, a read-only sandbox and disabled shell, apps, web search and subagents; its user configuration is not inherited. The bridge does not log prompts or responses. These controls do not override the CLI/model vendor's own service retention, diagnostics or account policies.

Use of information received from Google APIs will adhere to the Chrome Web Store User Data Policy, including the Limited Use requirements.

## Retention and user control

Library records remain in the current Chrome profile until removed or replaced by the user, or until the extension's local data is cleared. Users can edit or delete papers and tags, export the library from Settings, and remove the extension to remove its extension-managed local data. Importing a library replaces the current library; export a backup first. Chrome profile copies and filesystem backups must be managed separately.

Removing records or uninstalling the extension does not delete JSON backups, downloaded clip images or the optional bridge token file from disk. Users can remove those files themselves. JSON backups contain library text and image paths, not model credentials or copies of downloaded image bytes.

Users choose whether to configure a model, which backend to use, whether to enable automatic tag descriptions, and when to start or update topic analysis. Disabling automatic tag descriptions does not disable other model operations such as translation or recommendations. To stop model processing, remove the configured credentials / connection or stop the local bridge, and do not invoke model operations. API keys can also be revoked with the provider. Settings can be removed by clearing the extension's data or uninstalling it.

External requests necessarily expose normal connection information, such as an IP address, to the destination. Metadata services, source websites and selected model providers apply their own retention and privacy policies. Paper_Mind cannot delete data already processed by those services. The project does not run a central copy of a user's library, collect advertising profiles, sell user data or use it for unrelated advertising or credit decisions.

## Contact and policy changes

The Paper_Mind project maintainers can be contacted through [GitHub Issues](https://github.com/ZJU-OmniAI/Paper_Mind/issues). Issues are public: do not include API keys, bridge tokens, private papers or other sensitive content. Once a store listing is published, its verified support contact may also be used. Changes to this policy are published in this repository with an updated date.
